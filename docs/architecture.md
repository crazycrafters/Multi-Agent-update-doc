# Architecture

Next.js proxies same-origin API requests and replayable SSE to FastAPI. TanStack Query loads persistent views. A provider adapter runs the three separate agents through either OpenAI Responses or the pinned Codex app-server JSON-RPC protocol. Both validate Pydantic structured outputs; each provider has timeout handling. OpenAI uses SDK retry; Codex failures support explicit checkpoint retry. Only the resume agent receives a web-search tool, only during consented research. LangGraph routes the persisted phase into the appropriate handler. Each external operation has an AgentExecution record and cached completed output. SQLAlchemy stores typed interview records, immutable versions, evidence links and audit history. Alembic owns schema changes.

PostgreSQL is the Compose database; SQLite supports lightweight development and deterministic tests. The orchestrator uses one API worker. Application-local locks serialize mutations for a resume; do not run multiple backend workers/replicas. A distributed deployment needs database leases, a durable job queue, authentication, authorization and shared rate limiting before horizontal scaling.

Each durable interview step creates a question, then an answer, then an evaluation. Ten primary questions may each receive one adaptive follow-up. Context includes the current transcript and the most recent twenty earlier questions. No fixed iteration limit exists. Both initial drafting and post-interview revision undergo an independent audit. Resume activation, provenance and revisions commit in one transaction.

Pause stops after the current durable step; it does not abort an already billed request. Cancel prevents further version activation. Recovery pauses in-progress iterations until the user explicitly resumes. Completed provider outputs are reused; a crash after external success but before persistence can repeat that request. Exactly-once billing is not promised. An iteration that reaches approval never schedules the next cycle automatically.

SSE events persist with increasing IDs. Clients reconnect using an event cursor. Events contain observable outputs, tool results and concise rationales, never hidden reasoning. Interview answers stream observable text snapshots through persisted SSE events; final structured answers and evaluations remain separate durable records.


Codex uses a dedicated managed credential directory and an app-server child process over stdio. Application secrets are excluded from its inherited environment. Each iteration/agent has its own persisted thread ID; resume-agent audits have an independent channel, and research has a separate channel with only generic topic queries. Research sources are accepted only when their URLs occur in observed web-tool results/actions. Shell execution, patch tools, plugins, connectors, delegation and MCP servers are disabled; unexpected server tool requests are rejected. The process works in an isolated empty directory with read-only sandbox policy. Provider selection and iteration launch share a lock. Recovery requires the iteration's original provider.


## Profiles and RAG

Profile IDs scope knowledge documents, chunks, retrieval, embedding operations and exports. Legacy resumes migrate into separate profiles, preserving existing evidence and versions. Documents retain original source, kind/status, project and version. Revisions archive the previous document instead of overwriting it. Retrieval filters both document and chunk profile IDs and active status before ranking. PostgreSQL full-text and exact pgvector cosine search combine using reciprocal-rank fusion. SQLite is a development/test fallback with lexical/cosine retrieval. Only retrieved excerpts from knowledge documents are sent to agents; public references never become personal evidence. Answers persist validated retrieved chunk IDs. Confirmed personal knowledge can support revisions through source-linked evidence records, while contradicted personal knowledge blocks automatic changes until resolved.

Run settings are snapshotted in iteration checkpoints. A bounded, user-authorized batch may create successor iterations transactionally, carrying only its settings and consent/target snapshot. After the last iteration, the resume builder generates 2–4 short strategy options and pauses. A selected strategy runs a fresh proposal/audit, then waits for final review; starting another batch requires explicit approval. Lifetime iteration history has no cap. Optional workflow steps are editable; the evidence/audit gates and final strategy/review are fixed.
